# OpenClaw Pixel Agents 1.7.0 — Usage and easier setup

The **Usage** tab brings conversation-level token and cost reporting to the office. This release also includes first-run installation instructions and recovery from transient Gateway startup refusals.

## Conversation Usage

- Inspect recorded input, output, cache-read, cache-write and total tokens for the selected conversation instance.
- Read Gateway-reported USD cost estimates, model and context-window limit. These are recorded conversation totals, not current-task totals, a provider invoice or occupied-context measurements.
- Keep missing counters unknown and incomplete pricing visibly partial. Explicit reported zero remains zero; missing prices do not imply a free conversation.
- Refresh while the tab is visible, retain labelled last-known values on temporary read failures, and clear private state on Lock or target replacement.

Usage reuses the existing office key and paired **`operator.read`** grant. No provider billing credential or additional Gateway permission is needed. Gateways without the optional native `sessions.usage` method show an unsupported state while the other panels remain usable. See the [Usage guide](https://github.com/SweetSophia/openclaw-pixel-agents/blob/main/docs/task-access-setup.md#conversation-usage) for the measurement and privacy limits.

## Installation instructions

- Run `openclaw-pixel-agents setup` for a repeatable guide to private configuration, persistent storage, the collector, task access and startup.
- Unconfigured launches print the same guide and a configuration error, rather than starting an unconfigured office.
- A short installation notice points to the guide. npm may hide lifecycle output or disable install scripts; the explicit setup command works independently.

The guide and notice only print instructions. They do not generate credentials, write configuration, pair a device or start a service. Use `openclaw-pixel-agents --generate-key` when you explicitly want to generate your own office key.

## Reliability and dependencies

An explicitly retryable `UNAVAILABLE` Gateway handshake now reconnects with bounded backoff and the existing device identity/grant. Transient startup refusals no longer become permanent office authentication failures. Genuine authentication, scope and pairing failures remain terminal and need operator attention; pending requests are rejected without replay.

The release includes the qualified Pino, Vite/PostCSS and test-tool updates, plus the pinned Node 26.12.1 Alpine container image and CodeQL action update. The supported host Node.js range remains **`^22.22.2 || ^24.15.0 || >=26.0.0`**.

## Upgrade

```sh
npm install --global openclaw-pixel-agents@1.7.0
openclaw-pixel-agents --version
openclaw-pixel-agents setup
```

Restart your existing office process after updating. Retain its **`DATA_DIR`** and private configuration to preserve layouts, appearances, device identity and scoped grants. The npm launcher defaults to `~/.openclaw-pixel-agents`; source and Docker deployments should retain their configured data directory. An existing installation does not need a replacement office key or device identity.

Task/run history selection and new action controls belong to the next revamp phase; they are not included in 1.7.0.
