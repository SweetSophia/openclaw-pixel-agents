# OpenClaw Pixel Agents 1.5.0 — Results and delivered files

The new **Results** tab brings task responses and assistant-delivered files into the office. It shares the same conversation selection as Task and Conversation.

## What's new

- Read a verified **Result**, or a clearly labelled **Latest response** when completion is unconfirmed. A file appearing does not mark a task successful.
- Copy the displayed response text. When clipboard access is unavailable, including direct-IP HTTP, the text remains selectable with manual-copy guidance.
- Preview UTF-8 text and still PNG/JPEG/WebP images, download other transferable files, and explicitly open external links after seeing their destination host.
- Follow files for the canonical task run. When a run cannot be identified, the panel labels the broader conversation scope and warns that it may include earlier work.
- Use four keyboard-accessible tabs with two rows on narrow screens and 44px action targets.

## Access and compatibility

Results uses the existing office access key and paired **`operator.read`** grant. Sending does not need to be enabled. File discovery requires native `artifacts.list`, `artifacts.get` and `artifacts.download` methods that accept assistant, agent, session and run filters. Older Gateways retain task text with an explicit unsupported file-discovery state. Native transfers were verified with OpenClaw 2026.10.3.

Files are assistant-delivered outputs; this is not a workspace file browser. Scope is checked before and after transfer. Lock, close, hidden-page, conversation/task changes and observed source changes clear previews and cancel pending content. Gateway tickets stay on the server; no new public socket payload or permission is required.

Transfers are limited to 16 MiB actual bytes and 30 seconds, with two concurrent transfers and six content requests per minute per IP. Text previews are capped at 256 KiB; raster previews at 8 MiB and 16 million pixels. Animated images and active document formats such as HTML/SVG require download. See the [task-access guide](https://github.com/SweetSophia/openclaw-pixel-agents/blob/main/docs/task-access-setup.md#results-and-delivered-files) for details.

## Upgrade

```sh
npm install --global openclaw-pixel-agents@1.5.0
openclaw-pixel-agents --version
```

Restart your existing office process after updating. Keep its `DATA_DIR` and private configuration to retain layouts, appearances and the paired device grant. The npm launcher defaults to `~/.openclaw-pixel-agents`; source and Docker deployments should retain their configured data directory.

The Node.js requirement is unchanged: `^22.22.2 || ^24.15.0 || >=26.0.0`. No new dependency, office key or Gateway write grant is needed for Results. See [installation and key setup](https://github.com/SweetSophia/openclaw-pixel-agents#create-your-task-access-key).
