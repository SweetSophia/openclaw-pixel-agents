# OpenClaw Pixel Agents 1.6.0 — Workspace and reliability

The new **Workspace** tab brings read-only agent file browsing to the office. This release also makes stalled refreshes recoverable and keeps uncertain message submissions safe to retry.

## Workspace browsing

- Browse the selected agent's configured workspace without choosing a conversation. Open folders, follow breadcrumbs and navigate 50-entry pages.
- Preview supported UTF-8 text and still PNG/JPEG/WebP images, or download supported files after an explicit action. HTML/SVG source is displayed as plain text.
- Keep Workspace separate from Results: workspace files may belong to any conversation and do not prove that a task completed.
- See last-known metadata with its original observation time when a read fails. File actions resume only after a current read succeeds.
- Cancel pending reads and clear previews on folder/agent changes, closing, Lock, hidden pages or observed file/source changes. Private file content stays out of the public roster and sockets.

## Reliability improvements

- Manual Refresh and Check connection recover after a ten-second deadline, retain a visible failure and allow retry. Slow background Task/session/Results reads have their own sixty-second budget.
- Refreshing a later Workspace page stays busy until its first-page reload finishes or is cancelled; repeated clicks share that reload.
- Cancelled reads cannot replace a newer tab's loading or error state. Current failures take priority over a labelled previous manual failure.
- A timed-out message submission keeps its outcome unknown. Retry original submission reuses its original identity and message, preserving later edits to the draft and preventing a replacement send while the outcome remains uncertain.
- Workspace notices, keyboard focus and locked access-key drafts survive the relevant refresh and tab transitions.

## Access and compatibility

Workspace uses the existing office key and paired **`operator.read`** grant. No additional key or Gateway write permission is needed. The office key now also grants trusted operator access to the selected agent's workspace files.

The Gateway must advertise native **`agents.workspace.list`** and **`agents.workspace.get`** methods. Older Gateways show an unsupported message while other tabs remain usable. The office never falls back to reading arbitrary host paths. Native handlers were checked with OpenClaw 2026.10.3 using isolated synthetic files; no real agent task was submitted.

Workspace text is capped at **256 KiB** and images at **1 MiB** to stay within the existing Gateway frame budget. Unsupported binary formats and larger files remain unavailable with an explanation. These limits differ from delivered files in Results. See the [Workspace access guide](https://github.com/SweetSophia/openclaw-pixel-agents/blob/main/docs/task-access-setup.md#read-only-workspace-browsing) for details.

## Upgrade

```sh
npm install --global openclaw-pixel-agents@1.6.0
openclaw-pixel-agents --version
```

Restart your existing office process after updating. Retain its **`DATA_DIR`** and private configuration to preserve layouts, appearances, device identity and scoped grants. The npm launcher defaults to `~/.openclaw-pixel-agents`; source and Docker deployments should retain their configured data directory. An existing installation does not need a new office key or a fresh device identity.

The Node.js requirement remains **`^22.22.2 || ^24.15.0 || >=26.0.0`**. There are no dependency changes in this release. See [installation and key setup](https://github.com/SweetSophia/openclaw-pixel-agents#create-your-task-access-key) for a new office.
