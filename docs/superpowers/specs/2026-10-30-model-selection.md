# Private conversation model selection

## Intent and approved behavior

Delivery 5 of the approved phase-two roadmap lets an authorized office operator inspect the selected live conversation's native model catalog and explicitly change that conversation's selection. Extend the existing TypeScript/Express/React private-control owners; no new dependencies, generic RPC proxy, global configuration change, conversation reset, task submission or permission upgrade.

The user explicitly approved native per-conversation semantics after source audit: reject known-busy or activity-unknown sessions before dispatch, but do not promise future-turn-only changes. Native `sessions.patch` can mark a live switch pending; work starting after the idle check can switch or restart at a native safe opportunity. The confirmation must plainly warn about this race. An RPC acknowledgement does not prove a model has executed.

Alternatives considered: (1) native session selection with honest busy/race warnings — approved; (2) disable writes until an atomic idle-only native contract exists — stricter but blocks the requested delivery; (3) modify the native Gateway or write its storage directly — outside scope and rejected. The native owner remains authoritative.

## Closed private boundary

Use the existing read/write opt-in and paired `operator.read`/`operator.write` grants; no new administrator or approval authority. Model capability negotiation is independent of `canSend`: `models.list` and `sessions.patch` are optional additions and must not disable existing panels on method-specific rejection. Expose read/change readiness with an honest unsupported/permission explanation.

Protected, no-store POSTs under `/api/control/agents/:id/models` read `{target}` and `/api/control/agents/:id/model` apply `{target, selectionId, model}` (`model` is one exact canonical catalog ID or `null` for default reset). Reject extra keys, run IDs, mismatched route agents and metadata-bearing targets. Project client `ControlSession` objects to canonical network targets at both request boundaries; TypeScript types do not remove runtime metadata.

`shared/controlModels.ts` owns strict bounded requests/responses, canonical target identity and model text validation. Return only target, observation identity/time, observed current model, bounded safe choices, independent manual-selection/readiness facts, disabled reason and confirmed/unknown outcome with an optional reconciled snapshot. Reject malformed, duplicate or oversized native choices. Never expose private model facts through public roster, collector, socket, storage or logs.

Bounds: 500 choices; model IDs 512 characters; labels 128; observation identities 128; observations 100 for 60 seconds; four concurrent reads; ten new apply operations per minute; 1,000 process-local attempted operation identities, fail closed without eviction at capacity; existing private response-byte limit. Preserve unambiguous Unicode; reject control/bidi and malformed Unicode in identifiers/presentation. Production code remains focused and readable rather than compressed multi-statement logic.

Internal post-receipt reconciliation shares that four-active-read semaphore. If saturated, only internal readback may enter a bounded FIFO queue: ten waiters maximum, ten seconds maximum admission wait. Reserve a released slot for its queued internal reader before a public read can steal it; public reads fail closed immediately rather than queue. Retain the original epoch through queued and admitted work, fence authority/identity/source/readiness/disposal before reservation and verification, and remove timers/abort listeners on all exit paths. Timeout, overflow, invalidation or read failure after dispatch remains retained unknown, never receipt-only success or native replay. The 60-second apply-rate window is independently named and does not derive from observation lifetime. Server-only capability diagnostics distinguish missing methods (`unsupported`) from disabled/missing write authority or refused admin (`permission`); literal read-only rows remain `read-only`. Do not add a wire field or weaken other private readiness.

Model strings must not smuggle native auth-profile selectors. `sessions-patch-model-selection-Bf9bn2vg.mjs:75` calls `model-ref-profile-BNjB2hED.mjs:3-22`, which interprets a non-version/quantization `@suffix` after the last slash as an auth profile. Reject such ambiguous identifiers before dispatch, even if a catalog row advertises them; permit unambiguous native date/quantization suffixes only when they cannot carry a profile. Post-write receipt mismatch is too late to prevent an unintended auth-profile change. This surface changes a model only, never an account/profile selection.

Before native dispatch verify current registry ownership, canonical session/lifecycle/branch identity, current authority, known-idle/writeable state, unchanged observed model presentation and fresh catalog permission for the exact requested ID. Nonselectable means denied regardless of availability; unknown readiness is not invented success. Send only `{key, agentId, expectedSessionId, expectedLifecycleRevision?, model}`. Recheck identity/source after awaited work. A source event invalidates observations; connection replacement must not erase attempted-operation protection.

Bind an observation to one immutable apply payload. Identical duplicate confirmation requests coalesce or return the original result without another native write; changed payload is rejected. Retain the attempted record before dispatch, across HTTP abort, source invalidation and reconnect. A missing/malformed/late native reply or failed reconciliation is **unknown**, never replayed automatically. Deterministic local pre-dispatch rejection is distinct from a possible native attempt. A subsequent action requires explicit Refresh, fresh facts and a new confirmation; old operation identity never becomes a fresh write. These guards are process-local, not durable across server restart.

For confirmation, validate receipt identity and committed preference semantics, not only agreement between two displayed model strings. For every non-null RPC selection require the requested canonical resolved model, exact `entry.providerOverride`/`modelOverride`, `modelOverrideSource: 'user'` and `modelOverrideRouteResolution: 'resolved'`, even when the requested model equals configured default. For `null` require `modelOverrideSource: 'default'` and no own provider/model override or route-resolution fields. Then read back target identity and compatible presentation. If either cannot establish the result, show unknown; never equate saved preference with a successfully executed model or undo a concurrent native client. A valid reset receipt proves default provenance at that commit, not that a racing native client cannot subsequently change it; describe collapses the explicit-default marker and cannot prove it remains unchanged.

## Live-only accessible UI

Place `ConversationModel` in the live Conversation view, using the existing private access and canonical selection. Historical runs and new-conversation drafts cannot read or apply model changes. Preserve history, send/Stop/Steer, approvals and drafts. Effective current model is source-observed information, distinct from office roster summary and execution proof.

Show a labelled native select, bounded native choices, policy and readiness separately, and **Use configured default for this conversation**. Selecting or refreshing never writes. Apply opens an immutable confirmation naming agent, conversation/session, observed current model, requested model/default and the warning: **Work starting after the idle check may switch models or restart under the Gateway's native behavior. This is not a future-turn-only guarantee.** Cancel receives initial focus; local forward/reverse Tab cycles and Escape stay inside confirmation and restore usable local focus without closing the parent panel. Long IDs wrap, phone/short-window controls remain reachable.

The model confirmation is a nonmodal local decision within the parent detail panel's shared whole-panel modal boundary. Keep its named `role="dialog"` nonmodal (no `aria-modal`) and associate its exact race warning with `aria-describedby`. Disable model Apply, Refresh and select while this local decision is open and fence their render-current handlers; repeated/background attempts must preserve the same immutable dialog and Cancel/local keyboard focus, including with the real parent's disabled-state observer. External target/source/activity/authority changes must still invalidate it.

Prevent the native default focus action locally on capture-phase pointerdown, with mousedown fallback, only for disabled background model buttons/select outside the current confirmation. Do not globally stop propagation, poll/refocus the page, re-enable controls or suppress enabled confirmation actions/content, parent navigation, wheel or touchstart/touchmove defaults. Validate actual native hit targets and focus before/after down/up; disabled handlers alone do not prevent browser blur into the parent overlay.

Replace/close confirmation synchronously when target, source observation, capability, read-only state or selection changes, including before passive effect cleanup. Duplicate same-task clicks submit once. Expired observations require Refresh. Lock, close, hidden-document reads, credentials, target and history changes cancel/fence obsolete reads and clear obsolete private presentations. Authority/identity errors clear all payload-bearing views. Transient retained views keep the original observation timestamp and become visibly stale/non-actionable.

Hiding the page must not falsely cancel an admitted mutation or automatically retry it. Unknown outcomes remain latched across ordinary remount/visibility refresh until explicit Refresh acknowledges newly observed state. No browser persistence or public socket carries model payloads. A method-specific denial leaves unrelated private access intact.

Race the entire admitted HTTP/body promise against a 30,000 ms local settlement deadline without adding an AbortSignal/native cancellation. At or after that monotonic boundary, even before a delayed timer callback, settle locally as unknown, clear pending and retain attempted identity/uncertainty. Consume late resolve/reject outcomes without adopting them, overwriting fresh snapshots, clearing a newer pending operation or producing unhandled rejections. Explicit successful Refresh with valid new/unattempted locally fresh facts is the only acknowledgement path; timeout, remount and visibility are not acknowledgements.

Use private `performance.now()` expiry fixed at each read or reconciled apply request's start plus the existing 60,000 ms lifetime. Server `observedAt` stays unchanged for display, passes the strict representable-Date parser, and is not compared against the browser wall clock for local action authority. Slow responses consume the local budget; expired arrivals and transient retained snapshots are non-actionable. Enforce expiry synchronously at action admission as well as through one expiry-boundary timer with early-wakeup rechecking; do not rerender the catalog every second. Server TTL and source/identity/authority checks remain authoritative, with no skew-tolerance field, clock clamping or persistence added.
