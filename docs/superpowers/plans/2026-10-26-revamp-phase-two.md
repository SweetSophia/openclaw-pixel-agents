## Shared implementation and verification contract

Extend the existing server-side Gateway adapter, private office access boundary and accessible agent-detail panels. Keep public roster/collector data independent. New actions must use narrowly allowlisted native methods and verified agent/session/run identity, honour negotiated permissions, validate bounded untrusted inputs, and report unsupported capabilities honestly. Never fall back to arbitrary host filesystem access or a generic RPC proxy.

Reads cancel on Lock, closing, hidden pages and relevant selection/source changes. Stale data keeps its original verification time. Mutations require an explicit user action and visible target; uncertain outcomes must not cause automatic replay. Do not silently grant new scopes or send real agent tasks as smoke tests. Preserve layouts, appearances, current credentials and the user's README/screenshots.

Each delivery needs meaningful synthetic transport/service/route and UI regressions, appropriate types/coverage/build/package/audit checks and native browser verification for interactive changes. Independently review the complete initial PR and every later change before pushing. Each Ready push starts a full 15-minute window, after which current-head feedback, checks and protections are refreshed. Operationally failed reviewers receive fresh independent replacements; passing tests and enforced protections remain mandatory. A task is complete only after merge and required post-merge verification; publication additionally needs public registry and clean-consumer evidence.
